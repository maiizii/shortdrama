# 红果搜索漏季修复与验证

验证日期：2026-09-18。反馈案例为搜索“无限叠加攻击”，《普通弓箭手？我能无限叠加攻击力》有五季，原项目只找到第一、第二、第四季。

## 原因

原正式搜索只读取 `https://hongguoduanju.com/search/<关键词>` 的 `_ROUTER_DATA`。官网首屏通常返回 10 条，混有相关作品，而 `totalCount` 约为 200。原实现读了总数，没有继续取数，也没有另一条名称检索路径。不同季按 ID 去重，不是被同名去重逻辑误删。

直接给网页加 `page=2` 或 `offset=10&count=30` 仍返回首屏，不能据此实现有效分页。公开 App 实现使用 `/reading/bookapi/search/tab/v` 及 `has_more`、`next_offset`、`search_id`、`passback`，但依赖可用的 App 签名；本项目本次验证得到 HTTP 200 空响应，没有接入未经验证的分页或签名代码。

另一个因素是输入搜索框时只筛选本地剧库。原界面未突出这一点，且简单字符串匹配容易受标题标点、空格和当前分类筛选影响。

## 修复行为

- 正式搜索先读取官网名称索引 `/incent_resource/suggestion?app_id=8662&query=...&count=50`，再取官网搜索页，合并两路所有有效剧集。现有来源限流器按站源串行请求；优先名称检索，避免较慢网页占用名称请求的短时限。
- `count=50` 是上游请求参数，本次实测上游只返回 20 个候选。正式搜索不对返回结果再截断为 10 或 20 条；输入联想仍最多显示 10 个词。
- 名称结果只导入 `word_type=short_play_name` 且 `video_data` 有有效剧集 ID 的记录。小说候选、演员词条和缺少剧集元数据的名称不冒充可播放短剧。
- JSON 解析使用 `UseNumber()`，保留 19 位 ID 精度。按 ID 合并元数据，不按标题去重，各季及不同 ID 的同名剧都保留。
- 服务端先排标题命中，前端默认按标题相关度及自然季号排列。手动选择热度、日期等排序时尊重所选排序。
- 本地匹配归一化标点、空白、大小写和全角字符；空格分隔的多个片段也可匹配同一标题，例如“普通弓箭手 第五季”。
- 页面区分本地筛选与联网结果。当前分类隐藏联网结果时，提示隐藏数量，并可取消分类筛选而保留关键词。
- 整次搜索最多 20 秒，名称请求最多 5 秒，网页请求最多 12 秒。同词请求合并，最多 32 个在途查询；正常结果仍缓存 5 分钟、最多 64 个查询。单路失败但另一路有结果时返回结果和警告，不缓存这次部分成功，允许立即重试。失败且没有有效结果时不报成“没有找到”。
- 保留站源权限、来源代理和退避、取消请求、剧库合并保存及资料补全流程。修改查询或切换来源后，旧响应不能覆盖当前搜索。

`GET /api/ui/search?q=...` 保留 `query`、`data`、`total`、`saved`，新增 `source`、`limited` 和 `warning`。`total` 兼容旧接口，来自官网估计值并至少为当前返回条数；它不表示可翻页的精确总量。页面只显示实际取得的条数，不显示虚假的加载完成或加载更多。

## 真实接口结果

果果剧库本轮同步后请求“无限叠加攻击”，返回 13 部，官网估计总数为 100，五季均在返回结果中：

| 季 | 剧集 ID | 集数 |
| --- | --- | ---: |
| 第一季 | `7648238378667740184` | 60 |
| 第二季 | `7660841363813960729` | 77 |
| 第三季 | `7668626435891809342` | 74 |
| 第四季 | `7676092957392374846` | 108 |
| 第五季 | `7680168711512132633` | 117 |

多站源版此前另测“重生”，合并返回 21 部，均保留热度字段。条数与排序可能随上游数据变化。名称接口另返回过没有 `video_data` 的第六季词条，本次没有将它作为已验证剧集导入。

这次修复验证了反馈案例的漏季问题，以及不再只依赖官网 10 条首屏的取数方式。公开入口仍有取数范围限制，没有验证可用的连续分页，不能保证与红果 App 的全部搜索结果完全一致。
