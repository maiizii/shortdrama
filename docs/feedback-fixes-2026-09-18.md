# 2026-09-18 用户反馈修复与缓冲优化

果果剧库本次同步覆盖合并、Emby、分片准备、封面 DNS、按站源保存，以及 macOS 用户反馈的缓冲和连续切集问题。默认关闭“按站源分类保存”，保持已有目录；“优先原始 MP4 / HLS 播放”的既有设置继续沿用。

## 问题与处理

| 反馈 | 代码中的原因或判断边界 | 本次实现 |
| --- | --- | --- |
| 多数音轨为 HE-AACv2 时合并失败 | 原计划要求少数音轨转成多数 HE-AACv2，但内置 AAC 编码器不能生成该配置 | 音轨配置混杂且多数为非 LC 的 AAC 时，统一音轨为 AAC-LC。视频独立判断，兼容视频保持复制；同质 HE-AAC 仍直接合并。提前检查转换参数，失败保留进度 |
| 合并全集没有 Emby STRM | 原同步只枚举源站章节，没有本地合并文件条目 | 增加 Season 00 的合并版特别篇，生成 STRM / NFO；合并完成通知同步器，普通分集保留。仅剩成功合并记录也可纳入下载范围 |
| 媒体分片未完整生成 | 该文字是本地输出检查失败，不能据此认定需要代理；FFmpeg 不同平台的清单与初始化文件路径处理可能不同 | 设置独立工作目录，所有 HLS 输出使用相对名；只对处理结束后的输出不完整自动转入兼容链路，并释放失败缓存。取消、配额限制、源站拒绝或网络错误继续报告原原因 |
| 红果图床被判为内网 / 保留地址 | Fake-IP、DNS 污染等可能让公网域名解析为非公网地址；原日志没有具体 IP，不能确认用户实际解析值 | 已登记来源允许备用 DNS 重解析一次，验证全部结果并固定公网 IP 连接，保留 Host、SNI、TLS 校验与代理。记录被拒绝的 IP，内网地址和不安全重定向继续拒绝 |
| 希望按来源分目录 | 新目录需利用来源字段，旧路径必须稳定 | 增加 `download.groupBySource`，新下载和新 Emby 剧目保存到红果一级目录。通过目录归属标识及持久记录复用旧目录，不迁移已有文件；NFO、特别篇和自动保存的海报随剧目录放置 |
| macOS 12.6 缓冲短、下一集卡 | 当前兼容 MSE 播放仅缓存 30 秒，暂停后降到 5 秒；预缓存被接管后仍可能保留后台单线程；原生 HLS 后续批次准备偏晚 | 增加有界缓冲、暂停填充与配额恢复；接管预缓存后按前台处理，前台需要资源时可取消未接管的后台预备；提前准备原生 HLS 后续批次，并显示真实缓存范围 |

连续播放的浏览器回归还发现：兼容播放与下载预读根清单后丢失了 HTTP 重定向最终地址，导致相对分片请求落到旧目录并返回 404。已让共用的媒体解析函数同时返回内容和最终 URL，去掉仅原始播放生效的上下文补丁。主清单、独立音轨、初始化文件、密钥与分片都按所属清单的最终地址解析。

## 采用的开源实践

本次读取了以下固定版本的源码，采用其策略与职责划分。具体缓存值依据短剧点播、现有服务器资源限制及本地验证选择。

| 参考 | 可复用的实践 | 本项目的应用 |
| --- | --- | --- |
| [hls.js v1.7.3 配置](https://github.com/video-dev/hls.js/blob/v1.7.3/src/config.ts) | 前向时间、字节目标、后向缓存分别配置；网络错误采用有限次数的退避重试 | 内嵌 hls.js 使用 60 秒基础目标、180 秒最大目标、48 MiB 字节目标、20 秒后向缓存；移除把清单和分片重试一律压成 1 次的覆盖，沿用库的加载策略 |
| [hls.js v1.7.3 BaseStreamController](https://github.com/video-dev/hls.js/blob/v1.7.3/src/controller/base-stream-controller.ts) | `getMaxBufferLength` 结合码率和字节量决定窗口，`reduceMaxBufferLength` 在内存压力下收缩目标 | 自建 MSE 管道按追加压缩字节及媒体时长估算缓冲预算；遇到 `QuotaExceededError` 降低目标、释放已播放数据，并保留同一块待写入数据重试 |
| [Shaka Player v4.16.1 配置](https://github.com/shaka-project/shaka-player/blob/v4.16.1/lib/util/player_configuration.js) | 区分 `bufferingGoal`、`rebufferingGoal` 与 `bufferBehind` | 前向填充不与首次起播绑定，暂停仍可填充；后向释放单独控制。保持现有媒体管道，不引入第二套播放器或依赖 |

兼容 MSE 的基础前向目标为 90 秒，随倍速增加，最多 180 秒；根据约 48 MiB 压缩数据预算减小目标，通常保留后向 20 秒。配额不足时缩短目标与预算，后向最多保留 10 秒，待写入块最多重试 3 次；暂停且没有可释放数据时等待继续播放或取消，避免丢掉中间视频数据。关闭或切集会立即取消等待。

这些数值是缓冲目标，不是浏览器实际分配内存的保证。分片或一次网络读取可能超过时间目标，浏览器也可能提前回收缓存；hls.js 的 `maxBufferSize` 本身不是进程内存的硬上限。高码率和旧设备仍需较低清晰度或更好的持续吞吐。

原生 MP4 / HLS 继续由浏览器决定缓存长度，保留苹果设备原生 HLS 优先。服务端兼容 HLS 仍每片约 2 秒、每批 12 片，但提前准备约 24 片的前向窗口，并维持 96 MiB 缓存上限及前向字节检查；下一集尚未接管时只预生成第一批。

下一集准备只在当前播放有余量时进行：兼容链路要求当前集完整缓冲、预计剩余观看时间不超过 45 秒；原始链路只解析链接，预计剩余不超过 60 秒且实际缓存至少够约 15 秒观看时可开始。处理资源被占满时，前台可以取消尚未接管的后台预备；已经接管的缓存受前台保护，继续使用常规有界线程数。

## 目录与 Emby 使用

管理员在“更多 → 代理 / 设置”勾选“按站源分类保存下载和 Emby 内容”，点击“保存并应用”。默认关闭，保存后对新剧立即生效：

```text
下载根目录/
└── 红果/
    └── 剧名/
        ├── .drama-id
        └── 001.mp4

Emby输出目录/
└── 红果/
    └── 剧名 [ID摘要]/
        ├── .juku-emby.json
        ├── tvshow.nfo
        ├── poster.jpg
        ├── Season 01/
        │   ├── S01E001.strm
        │   └── S01E001.nfo
        └── Season 00/
            ├── S00E001.strm
            └── S00E001.nfo
```

海报扩展名按实际格式保存；仅自动同步下载本地海报，手动 ZIP 仍包含 STRM、NFO 及签名海报 URL。生成本地海报无需 Emby API Key；API 配置用于通知扫描及远端海报同步。已有自定义海报或被用户修改过的图片保留，取图失败不影响文字媒体文件。

开关切换、剧名更新、任务清理和重启均复用已登记的原目录。识别出多个同剧目录时停止新建，防止产生第三份；同名跨来源使用各自的来源目录。已有下载和 STRM 不自动移动。保留 `.drama-id`、`.juku-emby.json`、`ui-state.json`、`emby-sync.json` 与 `emby-key`。

合并版的 `Season 00/S00E001.strm` 指向签名的本地 MP4 接口，支持 GET / HEAD / Range，检查账号当前权限，不要求 FFmpeg 或源站在线。源站章节查询失败时，已有合并文件仍可单独导出；未合并的剧仍报告章节错误并保留旧导出。
