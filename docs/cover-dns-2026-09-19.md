# 2026-09-19 Docker / mihomo TUN 封面 DNS 修复

反馈提到的检查确实会拒绝 mihomo 常用的 `198.18.0.0/15` Fake-IP。这是保留地址段，代码另外还拒绝回环、私网、链路本地等地址。检查对象是封面域名解析得到的目标 IP；Docker 使用 `127.0.0.11` 作为 DNS 服务器，或使用局域网代理，本身不会触发这项检查。只有 DNS 答复中的目标地址被判为非公网时，才会进入该处理分支。

## 本次发现

- 果果剧库已有封面重解析分支，却没有在 `NewDownloader` 创建客户端时设置备用解析器。此前测试直接注入 `fallback`，未覆盖实际初始化遗漏。本次从真实客户端入口复现：系统解析返回 `198.18.0.42` 后，果果版未向配置的本地代理发送任何备用 DNS 请求，直接报错；多站源版会请求备用 DNS。
- 多站源版的 DoH 解析只排除了部分私网地址，会把 `198.18.0.0/15` 等保留地址当作可用结果并提前结束查询，随后才被封面连接层拒绝，因此没有继续尝试第二个 DNS 服务。

## 当前行为

两版的 `newImageTransport` 默认创建相同的 DNS 解析器。已登记来源遇到 Fake-IP、私网解析、空结果或解析错误时，按已有回退流程通过 HTTPS DNS 重新解析；不再依赖调用方手动接入。服务依次为 `dns.alidns.com`、`dns.google`，每次服务请求最多四秒，保留原有备用解析的 ECS 参数、TTL 缓存与并发请求合并。

备用服务返回的整组 A 记录都要通过公网校验。虚拟地址、私网与公网混合的记录、保留地址、无效记录及失败响应都不能作为成功结果缓存，而是继续尝试下一服务。全部失败时报告原始拒绝地址及备用解析错误。

连接仍固定到验证后的公网 IP，保留原始 Host、TLS SNI、签名查询参数、来源头和配置的代理。私网字面量 URL、未登记来源的私网解析和不安全重定向继续拒绝。关闭空闲连接或切换代理时，也会关闭备用 DNS 客户端的空闲连接。

通用解析代码位于 `internal/app/network_dns.go`。多站源版原有专属 CDN 拨号逻辑拆到 `network_dns_cdn.go`；该文件没有同步到果果版。果果剧库的名称、红果来源限制、ID 校验及独立配置保持原有规则。

## 验证

测试只使用本地 HTTP / HTTPS 服务、DNS JSON 与文字响应，没有请求、查看或处理数据源图片，也没有生成测试图片。

- 实际 `NewDownloader` 与封面缓存入口：Fake-IP 触发默认备用 DNS，DNS 请求经过配置的本地 HTTP 代理；测试代理故意拒绝连接，以确认真实初始化与来源上下文传递。
- 实际客户端成功路径：公网解析无需备用请求；Fake-IP、Docker 常见私网地址、IPv6 私网、IPv4 映射地址、混合结果、空解析和解析失败均可恢复到本地文字响应。验证 Host、SNI、证书、签名参数、来源头、DNS 缓存与连接复用。
- 备用服务切换：覆盖虚拟地址、私网、回环、元数据地址、保留网络、混合地址、无效 A 记录、空记录、NXDOMAIN、非法 JSON 和 HTTP 错误；失败结果不缓存，取消请求停止解析。
- 拒绝路径：私网与 Fake-IP 字面量 URL、未登记来源、备用解析仍指向私网、混合备用记录及私网重定向，不建立未验证的目标连接。
- 保留既有公网 URL、HTTP / HTTPS 代理、来源权限及专用版来源边界回归。

两版分别通过相关 Go 回归与竞态检查，多站源版另通过原有浏览器传输隔离、证书校验、代理切换及来源限制检查，果果版通过红果专用缓存、搜索、榜单与任务边界检查。核心回归命令：

```bash
go test ./... -run '^(TestDNSResolver|TestDownloaderCoverDNSFallback|TestImageURL|TestImageTransport|TestImageSource)' -count=1 -timeout=90s
go test -race ./... -run '^(TestDNSResolver|TestDownloaderCoverDNSFallback|TestImageURL|TestImageTransport|TestImageSource|TestAccountSourceChoices|TestHongguoOnly)' -count=1 -timeout=120s
go run . -help
```

使用 Go 1.24.1、`CGO_ENABLED=0` 重建两版的 macOS arm64 / amd64、Linux amd64、Windows amd64 程序及对应 ZIP，共八个程序和八个压缩包。逐包校验 CRC，并核对包内程序与构建产物的 SHA-256。macOS amd64 成品通过本机 `-help` 启动检查。交付更新两边原有 `dist/` 中的对应文件。

本地模拟覆盖上述代码路径，未在反馈用户的 Docker、mihomo 配置或真实图片请求上实测。

## 更新与排查

使用对应项目的新版程序并重启服务；Docker 使用更新后的源码重建应用镜像，例如在原 Compose 项目目录执行：

```bash
docker compose up -d --build app
```

保留原有数据卷，无需清空剧库、账号或下载记录。若仍失败，查看同一时刻 `cover.failed` 的完整文字错误：被拒绝的 IP 用于区分 Fake-IP / 私网解析，后续 DoH 错误用于判断备用服务是否可达。配置代理时，容器必须能访问该代理地址；容器里的 `127.0.0.1` 指向容器本身。

若网络策略使两个备用 DNS 服务都不可达，需要使至少一个服务可达，或让相关 CDN 域名返回可用公网地址。单独删除私网检查无法确认目标地址是否正确，也不能解决所有代理连通问题。
